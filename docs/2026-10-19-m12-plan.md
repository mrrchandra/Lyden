# M12 Plan — Long-context scaling 1024 → 32K + CoT reasoning traces (100M)

**Approved:** 2026-10-19. Entry artifact: M11 `ckpt_0009600.pt` (+ tokenizer via `lyden-100m-backup`).
**Environment:** Kaggle T4×2 DDP, batch run (Save & Run All), dataset-attached, fail-fast guards — M11's launch path.

## Goal

Take the 100M hybrid (Mamba + selective-attention islands + MoE) from trained-window 1024 to a
usable **32K context** through in-run context warming, and teach visible chain-of-thought for
multi-hop fact questions via synthetic traces. No architecture changes — CoT is data.

## Design

### Context warming schedule (rope_base fixed at 10000; warming teaches positions)

| Phase | Window | Steps | ~step time | tokens/step |
|---|---|---|---|---|
| A | 2048 | 1,200 | ~4 s | 65K |
| B | 4096 | 700 | ~10 s | 130K |
| C | 8192 | 500 | ~25 s | 262K |
| D | 16384 | 200 | ~45 s | 524K |
| E | 32768 | 400 | ~1.5–2 min | 1.05M |

- ~4,000 steps total, ≈ 2.1B new tokens (~40× M11's budget), ~10–11 h on T4×2.
- Entry: ckpt_9600 with `training.reset_scheduler: true`, fresh cosine per phase; phase configs
  generated by a small script (`scripts/m12_warmup_configs.py`) — one YAML per phase.
- Micro-batch reduced (8 → 2) as windows grow; grad_accum scaled to keep effective batch tokens
  per optimizer step at ≤ ~130K (interior phases) so optimizer dynamics stay sane.
- `checkpoint_every: 200` stays; if the Kaggle 12 h cap bites, a second session resumes from the
  last ckpt (continuation machinery from M11, already tested).

### Data (scripts/m12_prepare_data.py — new, extends M11's sessions pipeline)

- Stream-pack TinyStories end-to-end (no per-story padding) to fill each window completely.
- Fact-fix CLM sessions: fact↔query distance stretched up to the phase's window (8K / 16K / 32K).
- **CoT traces (~12% of session data):** synthetic 2-hop chains — fact@pos p₁, bridging fact,
  query near window end, model-side trace written out ("via the barn") between question and answer.
- Recall probes for eval: fact at distance {8K, 16K, 32K}; 2-hop probes at ≤ 32K.

### Eval (scripts/m12_eval.py — extends M11's eval)

Success bar:
1. **Story ppl ≤ 15** (unchanged from M11).
2. **1-hop fact recall ≥ 0.80 at T=0** measured at distances 8K/16K/32K (all).
3. **Long-context ppl** at {512, 2048, 8192, 32768}: monotonic-ish, no collapse (32K ppl ≤ 2× best).
4. **Router health unchanged:** load_top ≤ 0.5, entropy ≥ 1.95 in all routed layers.
5. **2-hop CoT recall ≥ 0.60** (exploratory soft bar at 100M; report, don't gate on it).

### Reasoning (CoT) — data-side only

Autoregressive trace = "question → written intermediate → answer". The decode path is untouched;
generation shows the trace. If 2-hop recall flops at 100M, that is a M13 finding, not a blocker.

## Implementation order (TDD)

1. `m12_warmup_configs.py` — emits per-phase YAMLs (deterministic; unit test on emitted values).
2. `m12_prepare_data.py` — packing + distance-stretched sessions + CoT traces (property tests:
   every window fully packed, trace structure checked, distances sampled as configured).
3. `m12_eval.py` — multi-distance ppl + 1-hop/2-hop probes (integration test on tiny model).
4. config m12 phase YAMLs + `kaggle/lyden-100m-m12.ipynb` (M11 notebook cells, m12 scripts,
   GPU-adaptive train loop unchanged).
5. Local tests green → push notebook, dataset attach, verify guard in a 30-s batch smoke if
   possible, then full launch user-approved.

## Risks / notes

- RoPE extrapolation is the main unknown; warming phases are designed to adapt it. If phase-E
  ppl collapses, fallback: next run re-enters from phase-C ckpt with NTK base scaling (rope_base
  ×4 at 16K+ phases) — decision deferred until eval data exists.
- Wheel compile tax (~64 min) persists unless the wheels rider lands; defer to post-M12.
- gate_collapse warnings (M11): observe, do not fix in M12 (one variable at a time).
